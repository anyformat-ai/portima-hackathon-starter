# Agent guide: Portima × anyformat hackathon starter

You are helping a team turn two document types into structured data with anyformat, and measure it
field by field:

- **European accident statement** (constat amiable / aanrijdingsformulier): parties, vehicles,
  insurers, the 17 circumstance boxes, impact points and the sketch.
- **Car order form**: buyer, vehicle, options, price and financing.

Start by running the checks in **First run** below. Do not write new code before they pass.

## Layout

| Path | What it is |
|---|---|
| `af.py` | The CLI. `create`, `run`, `score`, `ground-truth`, `dataset`, `eval` |
| `workflows/<doc_type>/*.json` | One anyformat workflow per field group, in the REST create format |
| `samples/` | Synthetic PDFs (fictitious data). `*_scan.pdf` are degraded scans |
| `ground_truth/<doc_type>s/*.json` | The correct answer per sample, nested and typed |
| `ground_truth/_api/` | Generated by `af.py ground-truth`: the same truth in the dataset API format |
| `results/`, `reports/` | Written by `af.py run` and `af.py score`; not committed |
| `tools/make_samples.py` | Regenerates the samples and their ground truth |
| `docs/` | Workspace tour, ground-truth guide, optimizer guide |

## First run

```bash
cp .env.example .env            # then paste the key from https://app.anyformat.ai/api-key
uv sync
uv run af.py create order_form  # 2 workflows
uv run af.py run order_form     # 6 sample PDFs
uv run af.py score order_form   # accuracy per field + confidence threshold sweep
```

Expected: `order_05_modern_nl_bad_total` reports a failed `net-plus-vat-is-total` validation; the
form's printed total is 100 euros too high on purpose. Then do the same for `accident_statement`
(6 workflows).

## How the pipeline is built, and why

- **Parse `lite`** (the app calls it "Fast"): OCR only, no LLM, 12 credits a page. Start here. Try
  `standard` only on the fields that `score` shows are failing because of reading errors.
- **Extract `standard`**: the default extraction, 35 credits a page.
- **About 20 fields per extract.** Our rule of thumb: long schemas extract worse than short ones. A
  workflow takes exactly one extract after its parse, so each group of fields is its own workflow
  (`workflows/accident_statement/` has six). `af.py run` sends each document to every group and
  merges the fields. When you add a field, put it in the group it belongs to; split a group that
  grows past 20.
- **Validate**: deterministic rules (free) run after each extract. They never block a run; they
  label it. Use them to route documents to a broker.

## Rules for changing things

- Field names are the contract between `workflows/`, `ground_truth/` and the scorer. The ground
  truth is nested (`vehicle_a.vehicle.plate`); the scorer flattens it with `_`
  (`vehicle_a_vehicle_plate`). Rename in both places, or scoring silently loses the field.
- A field's `description` is where accuracy comes from: say where on the form it is (box number,
  the FR and NL label), the format you want, and when it is null.
- Object fields (`data_type: object`) are lists of rows, one level deep. There is no list type.
- Every value comes back as a string or null, with `confidence` 0–100 and `evidence` (the text
  it was read from and its page).
- Editing a workflow JSON does not change the workflow in the workspace. Re-create it
  (`af.py create <doc_type> --force`) or edit it in the app's Studio.
- Uploads are limited to 60 per minute. `af.py` already waits between submissions.
- Never commit `.env`, `results/` or real customer documents.

## Typical asks and where to start

| Ask | Start in |
|---|---|
| "Accuracy on field X is low" | `reports/<doc_type>.md` misses, then that field's `description` |
| "Add a field" | The right file in `workflows/<doc_type>/`, plus the ground truth for every sample |
| "Make ground truth for our real documents" | `docs/GROUND_TRUTH.md` |
| "Pick confidence thresholds" | The sweep table in `reports/<doc_type>.md` |
| "Improve descriptions automatically" | `docs/OPTIMIZER.md` (dataset first, then the optimizer in the app) |
| "Where do I see this in the app?" | `docs/WORKSPACE.md` |
| "Compare with our own pipeline" | Write predictions in the shape of `results/<doc_type>/*.json` and reuse `af.py score` |
